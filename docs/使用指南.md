# 使用指南

这里描述如何读取仓库中的文件；使用素材前请先确认 [权利与来源](版权与来源.md)。

## 本地使用

```bash
git clone https://github.com/lliooly/wuwa-tappo-assets.git
cd wuwa-tappo-assets
python3 scripts/verify-assets.py
```

直接读取仓库内的 PNG、SVG、ICO 或 WOFF2 即可，例如 `assets/角色/完整图/role_1102_1001.png`。文件名及目录中的中文字符应按 UTF-8 处理。

## HTML 和 CSS

页面与仓库位于同一个静态站点根目录时，可以使用相对路径：

```html
<img src="./assets/角色/完整图/role_1102_1001.png" alt="角色素材">
```

```css
.character {
  background-image: url("./assets/角色/完整图/role_1102_1001.png");
  background-size: contain;
}
```

## 按图鉴读取

`data/catalog.json` 的 `items` 是数组。每项的 `files` 按 `image`、`atlas`，以及角色专有的 `body1`、`body2`、`body3`、`head1`、`head2` 分类；每个文件项包含相对于仓库根目录的 `path`、`sha256`、`dimensions`、`size` 和原始 `sourceUrl`。

```js
const base = "https://raw.githubusercontent.com/lliooly/wuwa-tappo-assets/main/";
const response = await fetch(new URL("data/catalog.json", base));
if (!response.ok) throw new Error(`图鉴请求失败：${response.status}`);
const catalog = await response.json();
const item = catalog.items.find(entry => entry.officialFilename === "role_1102_1001.png");
if (!item) throw new Error("未找到图鉴条目");
const imageUrl = new URL(item.files.image.path, base).href;
document.querySelector("img").src = imageUrl;
```

以上是读取静态 GitHub 原始文件的示例；`main` 内容可能随仓库更新。需要稳定版本时，请使用具体提交的完整 SHA 替代 `main`。GitHub 的访问策略、可用性和缓存不由本仓库保证。

## 角色分层和偏移

角色图像还包含两张头部和三张身体分层。`item.files.head1.path`、`item.files.body1.path` 等提供实际路径。原始 `assetMetadata` 及其 `head1`、`body1` 等对象保留了 `offset_x`、`offset_y`、`my_offset_x`、`my_offset_y`；这些是上游数据，不应假设适用于所有画布尺寸。实际合成时需结合客户端的坐标系、缩放和动画状态验证。

图鉴 ID 与素材 ID 不一定相同：`atlasAssetId` 是图鉴条目的 ID，`assetId` 是该条目关联的素材 ID；`atlasMetadata.height_light_id` 保留上游原字段。未解锁与否属于账号状态，本仓库不包含该状态。
