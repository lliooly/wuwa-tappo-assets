# 使用指南

本指南帮助开发者按场景选择 Wuwa Tappo CN 1.0.2 的素材。开始前请阅读 [素材使用与维护规则](../AGENTS.md) 和 [版权与来源](版权与来源.md)。下文的原版行为依据客户端前端发行文件及 2026-10-30 公开索引快照；不同版本可能不同。

## 先按使用场景选图

`data/catalog.json` 中每个条目都有 `type` 和 `files`。`files.atlas` 表示图鉴用途，`files.image` 表示原素材用途：

| 画面或用途 | 条目类型 | 读取的字段 | 仓库目录 |
| --- | --- | --- | --- |
| 角色图鉴、背包物品格、奖励物品图 | `character_skin` | `files.atlas.path` | `assets/角色/图鉴图/` |
| 桌宠动态身体 | `character_skin` | 每帧从 `files.body1`、`body2`、`body3` 中选择一张 | `assets/角色/身体分层/` |
| 桌宠动态头部 | `character_skin` | 每帧从 `files.head1`、`head2` 中选择一张 | `assets/角色/头部分层/` |
| 单张完整角色的静态展示 | `character_skin` | `files.image.path` | `assets/角色/完整图/` |
| 配件图鉴、背包物品格、奖励物品图 | `accessory` | `files.atlas.path` | `assets/配件/图鉴图/` |
| 桌宠佩戴的配件 | `accessory` | `files.image.path` | `assets/配件/素材图/` |
| 表情图鉴、背包物品格、奖励物品图 | `emote` | `files.atlas.path` | 本快照指向 `assets/表情/素材图/` |
| 桌宠表情菜单、触发后显示的表情 | `emote` | `files.image.path` | `assets/表情/素材图/` |

**配件佩戴必须使用素材图。** 例如「冰盈舞者」的 [佩戴图](../assets/配件/素材图/accessory_1001.png) 和 [图鉴图](../assets/配件/图鉴图/accessory_1001.png)均为 560 × 560，但配件在透明画布上的位置不同。本快照中 135 对配件图、260 对角色图鉴图与完整图的文件内容均不相同，不能仅凭同名替换。

表情图和对应图鉴图在本快照的 504 对条目中逐字节相同，所以存为同一文件。调用时仍按场景读取 `files.image` 或 `files.atlas`；将来的版本不保证继续相同。表情是独立显示的图片，不是角色的头部分层。

角色的完整图适合需要一张静态角色图的场景。桌宠动态渲染，以及需要表现角色与配件组合的画面，应按下文使用角色分层和配件素材图。不要把完整图与同一角色的头、身体分层再叠加一遍。

## 桌宠合成与偏移

1. 查找同一角色外观条目，每帧各取一张头部分层和身体分层；需要配件时，从所选配件条目取 `files.image`。不要把不同角色或不同外观系列的分层混用，也不要将多个身体动作图同时叠加。
2. 保留每张图片的完整透明画布，将各层按相同的显示宽高和原点叠加。不要分别裁掉透明边缘、按可见图案居中，或假设图片像素尺寸都相同。例如「影烁者」的 [佩戴图](../assets/配件/素材图/accessory_1005.png) 是 1500 × 1500，其图鉴图是 560 × 560。
3. 原版桌宠的绘制顺序为头部、身体、配件：头部和身体在同一层级，身体后绘制；配件在上方。表情在独立的界面层显示。
4. 原版根据当前**角色**的 `assetMetadata.offset_x` 和 `offset_y` 平移配件层；没有角色素材元数据时，原版还会回退读取用户角色中的坐标。不要误用配件自身的偏移，也不要把这个平移应用到头部和身体。`my_offset_x`、`my_offset_y` 是另存的原始字段，不能当作配件偏移的同义词。
5. 这些偏移属于原版渲染坐标系。改变显示尺寸或缩放时，应结合原版逻辑与实际画面验证；不要假设偏移可直接用于任何尺寸。`body1`～`body3`、`head1`～`head2` 的具体动作和切换时机应依据原版行为核实，不能只凭编号猜测。

### 选图与叠层示例

以下示例使用原版默认的 200 CSS 像素画布，展示如何选出同一角色的头、身体及配件。它说明静态叠层与字段选择，未实现完整动作、缩放或缺省处理。页面需要有网络访问 GitHub 原始文件。

```html
<div class="pet" aria-label="角色与配件示例">
  <img id="pet-head" alt="">
  <img id="pet-body" alt="">
  <img id="pet-accessory" alt="">
</div>

<style>
  .pet { position: relative; width: 200px; height: 200px; }
  .pet img { position: absolute; inset: 0; width: 100%; height: 100%; }
</style>

<script type="module">
  const base = "https://raw.githubusercontent.com/lliooly/wuwa-tappo-assets/main/";
  const response = await fetch(new URL("data/catalog.json", base));
  if (!response.ok) throw new Error(`图鉴请求失败：${response.status}`);
  const { items } = await response.json();

  function findItem(type, filename) {
    const item = items.find(entry => entry.type === type && entry.officialFilename === filename);
    if (!item) throw new Error(`未找到素材：${type} / ${filename}`);
    return item;
  }

  function fileUrl(item, key) {
    const path = item.files[key]?.path;
    if (!path) throw new Error(`素材缺少 ${key}：${item.officialFilename}`);
    return new URL(path, base).href;
  }

  const character = findItem("character_skin", "role_1104_1002.png");
  const accessory = findItem("accessory", "accessory_1001.png");
  document.querySelector("#pet-head").src = fileUrl(character, "head1");
  document.querySelector("#pet-body").src = fileUrl(character, "body1");
  const wornImage = document.querySelector("#pet-accessory");
  wornImage.src = fileUrl(accessory, "image");
  const { offset_x = 0, offset_y = 0 } = character.assetMetadata;
  wornImage.style.transform = `translate(${offset_x}px, ${offset_y}px)`;
</script>
```

图鉴或背包物品格若要显示同一配件，应读取 `fileUrl(accessory, "atlas")`，不要使用上面的佩戴图。

## 界面、图标和字体

下面列出按用途查找的位置；具体控件的状态和切图方式仍需对照原版，不能仅凭文件名前缀推断全部行为。

| 场景 | 资源位置和示例 |
| --- | --- |
| 主界面导航 | `assets/界面/原版/nav-*`，包括图鉴、背包、房间、设置、合成以及 `-active` 状态。 |
| 图鉴、物品格和物品类别 | `assets/界面/原版/atlas-*` 为图鉴相关界面素材；`type-icon-character`、`type-icon-accessory`、`type-icon-emote` 为类别图标。物品内容仍取对应条目的 `files.atlas`。 |
| 预设与表情位 | `assets/界面/原版/preset-*`、`preview-main*`、`preview-emote-*` 是预设及槽位界面素材；实际表情另取表情条目的 `files.image`。 |
| 桌宠信息、房间和合成 | 分别查找 `assets/界面/原版/pet-info-*`、`rooms-*`、`synthesis-*`。 |
| 宝箱、奖励和稀有度装饰 | 查找 `assets/界面/原版/chest-base-*`、`reward-*`、`*-star`、`*-ray`、`ribbons-*`；奖励的物品内容仍取 `files.atlas`。 |
| 通用面板、控件及更新画面 | 查找 `assets/界面/原版/module-*`、`panel-*`、`close*`、`select-*`、`circle*`、`bubble*` 和 `update-bg.jpg` 等。 |
| 登录选择、UID 登录 | 分别查找 `assets/界面/原版/login-select/` 和 `assets/界面/原版/uid/`。 |
| Windows 安装、卸载画面 | 查找 `assets/界面/原版/installer/`。 |
| 登录 SDK 界面 | 查找 `assets/界面/登录SDK/`；这是 2026-10-30 的 SDK 快照，不能直接视为客户端发布时的 SDK 版本。 |
| 平台图标 | `assets/图标/Windows原生/app.ico` 及其各尺寸 PNG 对应 Windows 原生图标；`assets/图标/发行包/app-icon.png` 和 `favicon.png` 分别为发行包应用图标及网页图标。`tauri.svg`、`vite.svg` 是发行包内的框架标识，不是桌宠图标。 |
| 页面文字 | `assets/字体/` 中的 WOFF2；使用前查看 [字体授权](字体授权.md)。 |

原版 CSS 的语言字体映射如下（每组前者为常规文字、后者为加粗文字）：

| 语言 | 字体家族 |
| --- | --- |
| 简体中文 `zh` | `975MaruSC` / `975MaruSC-Bold` |
| 繁体中文 `tw` | `SourceHanSansCN-Medium` / `SourceHanSansCN-Bold` |
| 英语、法语、德语、西班牙语、葡萄牙语 | `GenSenRounded-M` / `GenSenRounded-B` |
| 日语 `jp` | `GenSenRoundedJP-M` / `GenSenRoundedJP-B` |
| 韩语 `kr` | `NanumGothic-Bold` / `NanumGothic-ExtraBold` |
| 泰语 `th` | `Prompt-Medium` / `Prompt-Bold` |

这是原版前端的字体设置；实际应用仍需处理字体覆盖范围、回退和各字体许可。

## 内置默认素材与历史名称

`assets/角色/内置默认/`、`assets/配件/内置默认/` 和 `assets/表情/内置默认/` 记录原客户端内置素材。其中与现有文件内容相同的素材只保存一份，各目录的 README 给出映射；历史路径也可查 `data/aliases.json`。别名是名称到实际路径的记录，不是仓库中的实体文件或符号链接。

需要注意，`role_1502_1001` 的内置完整图和头身分层与公开索引中的同名文件内容不同，所以内置版本保存在 `assets/角色/内置默认/character/`；公开索引版本则由 `catalog.json` 指向其他角色目录。同一次合成应使用同一来源的一组角色文件，不要仅凭文件名混用。`role_1501_1001` 的内置角色文件则通过别名指向已保存的相同文件。

## 本地使用与按图鉴读取

```bash
git clone https://github.com/lliooly/wuwa-tappo-assets.git
cd wuwa-tappo-assets
python3 scripts/verify-assets.py
```

直接读取 PNG、SVG、ICO 或 WOFF2 时，文件名和目录中的中文字符应按 UTF-8 处理。页面与仓库位于同一个静态站点根目录时，例如：

```html
<img src="./assets/角色/完整图/role_1102_1001.png" alt="散华静态角色图">
```

```css
.character {
  background-image: url("./assets/角色/完整图/role_1102_1001.png");
  background-size: contain;
}
```

`data/catalog.json` 的 `items` 是数组，每项包含条目类型、名称、ID 和 `files`。文件项包含相对于仓库根目录的 `path`、`sha256`、`dimensions`、`size` 和原始 `sourceUrl`。查找时同时限定 `type` 与 `officialFilename` 或对应 ID；图鉴 ID `atlasAssetId` 和素材 ID `assetId` 不一定相同，原始关联字段 `atlasMetadata.height_light_id` 也予以保留。不要将同名文件的路径直接拼接成其他用途。

上方 GitHub 原始文件示例使用 `main`，内容可能随仓库更新。需要稳定版本时，请将 `main` 换成具体提交的完整 SHA；GitHub 的访问策略、可用性和缓存不由本仓库保证。

找不到指定用途的字段或文件时，应明确报告缺失或显示占位状态，不要静默改用图鉴图或其他类型的图片。素材文件存在不代表账号已经解锁；解锁状态需来自应用自身的账号数据。

## 依据与核对

角色分层、配件和表情的选图规则来自原客户端恢复的前端发行文件 `index-CuzHFfJW.js`、`index-pp8VWaUF.js` 及 `index-C3fG-hsi.css` 的静态分析；图鉴、背包和奖励物品图使用图鉴资源，桌宠配件及表情使用对应素材资源。原始文件未随本素材仓库发布。

原始公开索引、图片 URL、ID 和偏移信息见 [来源快照](../data/来源快照/)；仓库内实际路径和哈希见 [catalog.json](../data/catalog.json)、[files.json](../data/files.json) 与 [aliases.json](../data/aliases.json)。运行 `python3 scripts/verify-assets.py` 可核对归档文件、图鉴路径和别名。
